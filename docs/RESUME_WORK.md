# 新对话续接指南

## 正确的项目目录

源码目录是 `finance-app-private-release`。不要从其他历史副本继续开发，也不要把本机私人计划 JSON 复制进仓库。

## Git 与发布

- `main` 保存可维护源码。
- `gh-pages` 保存 Vite `dist` 的静态发布结果。
- 正式地址是 <https://fssserenalee-blip.github.io/zhiyu-mobile/>。
- 发布前先构建，再把生成的 `index.html`、`404.html`、`service-worker.js` 和当前哈希资源复制到发布分支。
- 每次涉及启动逻辑或离线资源的发布都要更新 service worker 的缓存名称，避免主屏幕应用长期停留在旧版。
- 不允许强制推送、重写公开历史或删除用户可能仍在使用的旧哈希资源。

## 关键代码位置

- `src/FinanceApp.tsx`：业务状态、自然月周期、记账、预算、计划、快捷指令、导入和界面。
- `src/personal-plan.ts`：私人计划格式验证、链接解码和计划合并。
- `src/persistence.ts`：IndexedDB 状态、日快照、持久化申请与完整性检查。
- `src/globals.css`：桌面和手机布局、主题和招财猫页面样式。
- `public/service-worker.js`：离线缓存与网络优先导航。
- `tests/personal-plan.test.mjs`：个人计划格式和合并回归测试。

## 必须保持的兼容规则

1. 自然月周期固定为每月1日至月底。
2. 导入或调整个人计划不能删除流水和已付记录。
3. 定投记为现金流出和储蓄投资，但不占日常消费预算。
4. 固定账单可以单列，不占日常额度。
5. `?quick=1` 继续直接聚焦金额输入框。
6. `#sms=` 和 `#text=` 快捷指令入口继续兼容。
7. 主屏幕应用与 Safari 可能拥有不同存储空间，用户必须在实际使用的主屏幕应用内导入计划。
8. 每次状态变化同步写入 localStorage 恢复副本，并异步写入 IndexedDB。

## 产品下一阶段

当前计划将试行两至三个月。下一阶段应以真实流水为依据复盘：

- 实际必要支出的月均值与波动范围。
- 食品日用、自由消费和网购的超限频率。
- “其他”分类中反复出现、应独立成类的项目。
- 固定账单是否遗漏或日期、金额是否需要修正。
- 定投扣款识别和计划完成率是否准确。
- 预算应该维持、放宽还是收紧。

未经用户确认，不要自行改变其个人预算金额或投资安排。
